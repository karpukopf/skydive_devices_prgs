# Репозиторий прошивок

Здесь хранятся файлы прошивок (`.bin`) и их описания. Это единственный источник правды:
- хостинг файлов (Cloudflare Pages) раздаёт `.bin` по адресу `https://files.<ваш-домен>/<прибор>/<версия>.bin`;
- сайт берёт отсюда описания версий и строит по ним страницы приборов и JSON для мобильного приложения.

## Устройство репозитория

```
firmware/
  arient/
    1.4.2.md     описание версии (данные, summary и список изменений на трёх языках)
    1.4.2.bin    сам файл прошивки
  aura/
    ...
  _headers       заголовки для хостинга файлов
config.json      адрес хостинга файлов (filesBaseUrl)
scripts/         new-firmware.mjs (создать релиз), check.mjs (проверить)
.github/         автоматическая проверка и пересборка сайта
```

Имя папки прибора (`arient`, `aura`) должно совпадать с именем файла прибора на сайте
(`src/content/devices/<язык>/arient.md`) и с ключом в JSON для приложения. Не переименовывайте его после выпуска приложения.

## Первая настройка

1. Создайте репозиторий на GitHub (публичный проще; приватный тоже работает, см. README сайта про `FIRMWARE_TOKEN`) и загрузите туда этот проект.
2. Откройте `config.json` и впишите настоящий адрес хостинга файлов, например `https://files.вашдомен.com`.
3. Выполните `npm install`.
4. **Хостинг файлов.** Cloudflare Pages, Create project, подключить этот репозиторий.
   Build command оставьте пустым, Build output directory: `firmware`. Затем Custom domains и добавьте `files.<ваш-домен>`.
5. **Автоматическая пересборка сайта.** В проекте сайта на Cloudflare Pages создайте Deploy hook
   (Settings, Builds and deployments, Deploy hooks). В этом репозитории откройте Settings, Secrets and variables, Actions
   и добавьте секрет `SITE_DEPLOY_HOOK` с адресом хука. Без него всё работает, но сайт придётся пересобирать вручную.
6. В проекте сайта задайте `FIRMWARE_REPO=владелец/этот-репозиторий` (Cloudflare Pages: Variables and Secrets, а локально в файле `.env`).

## Каналы: стабильный и бета

Канал определяется по версии, отдельного поля и отдельных git-веток не нужно:

| Версия | Канал | Пример |
|---|---|---|
| без суффикса | стабильный | `1.5.0` |
| с суффиксом `-beta.N` | бета (тестовые функции) | `1.5.0-beta.1`, `1.5.0-beta.2` |

Бета-версии лежат в тех же папках, что и стабильные (`firmware/arient/1.5.0-beta.1.md` и `.bin`). На сайте они показываются
отдельным блоком «Бета» с предупреждением, а в JSON для приложения лежат в `channels.beta`. Стабильный канал
(`latest`, `history`, `channels.stable`) бета-версии не содержит.

Порядок работы: тестируете `1.5.0-beta.1`, `1.5.0-beta.2`, ..., а когда всё в порядке, собираете финальную прошивку и
выпускаете её как `1.5.0`. Версия `1.5.0` считается новее любой `1.5.0-beta.N`.

Третий канал (например, `rc` или `nightly`) добавляется правкой регулярного выражения версии в `scripts/*.mjs` и
в схеме сайта. Обычно двух каналов достаточно.

## Как выпустить прошивку

```
npm run new-fw -- arient 1.4.3 ./firmware.bin "Short summary in English"
npm run new-fw -- arient 1.5.0-beta.1 ./firmware-beta.bin "Test build with ..."   # бета
```

Скрипт копирует файл в `firmware/arient/1.4.3.bin`, считает SHA-256 и размер и создаёт `firmware/arient/1.4.3.md`.
Откройте его и допишите:

- `summary` на английском (обязательно), испанском и русском: одна строка, её увидят покупатели и приложение;
- `changes`: списки `added`, `changed`, `fixed` на трёх языках (лишние блоки можно удалить);
- при необходимости `minAppVersion`: минимальная версия приложения для этой прошивки.

Пустые испанский и русский не страшны: на сайте покажется английский.

Дальше:

```
npm run check
git add .
git commit -m "arient 1.4.3"
git push
```

После `push` GitHub повторит проверку, хостинг выложит файл, и примерно через две минуты сайт пересоберётся и покажет новую версию.

## Правила

- **Опубликованные файлы не заменяют.** Ошибку исправляют новой версией. Файлы `.bin` кэшируются на год, а приложение запоминает SHA-256.
- **Черновик.** `draft: true` в описании: версия не попадёт ни на сайт, ни в JSON. Файл `.bin` при этом всё равно будет доступен по прямой ссылке, поэтому секретные сборки здесь не храните.
- **Что проверяет `npm run check`:** формат версии (`1.4.2` или `1.5.0-beta.1`) и дат, соответствие имени файла и содержимого, наличие `.bin`, совпадение SHA-256 и размера с настоящим файлом, правильный адрес в `url`. При ошибке проверка в GitHub падает, и сайт не обновляется.

## Формат описания

```yaml
---
device: arient
version: 1.4.2
date: 2026-09-20
url: https://files.example.com/arient/1.4.2.bin
sha256: <64 символа, считает скрипт>
size: 184320
minAppVersion: 2.1.0        # необязательно
draft: false                # необязательно
summary:
  en: Fixed calibration at low temperatures
  es: Corregida la calibración a bajas temperaturas
  ru: Исправлена калибровка при низкой температуре
changes:
  en:
    fixed:
      - Altitude calibration below -10 °C.
    changed:
      - Battery indicator is more accurate.
  es: { ... }
  ru: { ... }
---
```

## Репозиторий вырастет

В репозитории лежат все файлы всех версий, и сайт скачивает его целиком при каждой сборке. Для десятков версий по несколько сотен КБ это незаметно.
Если когда-нибудь файлов станет слишком много, `.bin` можно вынести в отдельное хранилище (например Cloudflare R2), оставив здесь только описания.
